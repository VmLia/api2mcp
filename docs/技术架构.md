# API2MCP 技术架构文档

**记录项目的详细技术架构设计**

## 一、项目概述

API2MCP 是一个将传统 REST API 转换为 MCP (Model Context Protocol) 工具的平台，使 AI Agent 能够通过 MCP 协议调用各种 REST API。

### 核心功能

1. **API 注册与管理** - 创建、配置、管理各种 REST API 的 MCP 转换规则
2. **Smart Parser** - 智能解析 OpenAPI/Swagger 文档，自动生成 MCP 工具定义
3. **API2MCP 引擎** - 将 REST API 转换为 MCP 协议格式，执行 API 调用
4. **MCP Server** - 提供 MCP JSON-RPC 2.0 协议端点，供 AI Agent 调用转换后的工具
5. **状态管理** - 请求追踪、服务监控、调用统计（基于 Redis）

### 2.3 核心模块详解

#### API Registry (API 注册模块)
- **路径**: `backend/src/api2mcp/api_registry/`
- **职责**: 管理 API 工具的注册、配置、鉴权、环境变量等
- **路由前缀**: `/serverapi/apimng`

**数据实体**:
| 实体 | 说明 |
|------|------|
| `Api2mcpBaseinfo` | 工具基础信息（MCP名称、版本、描述、API端点、HTTP方法等） |
| `Api2mcpParameter` | 参数定义（参数名、类型、描述、示例、必填等） |
| `Api2mcpAuthConfig` | 鉴权配置（API Key、Bearer Token、OAuth等） |
| `Api2mcpEnvVariable` | 环境变量（全局或工具级别的变量替换） |

**服务**:
| 服务 | 说明 |
|------|------|
| `BaseinfoService` | 工具基础信息 CRUD、MCP 定义生成 |
| `ParameterService` | 参数管理（树结构） |
| `AuthService` | 鉴权配置管理 |
| `EnvVariableService` | 环境变量管理 |
| `SmartParserService` | 智能解析 OpenAPI 文档 |

#### Engine (转换引擎模块)
- **路径**: `backend/src/api2mcp/engine/`
- **职责**: 将 REST API 转换为 MCP 协议格式并执行调用
- **核心服务**: `MCPService`

**MCPService 主要方法**:
| 方法 | 说明 |
|------|------|
| `get_tools(tool_id)` | 获取工具列表（支持项目隔离） |
| `invoke_tool(tool_name, arguments, tool_id)` | 调用指定工具 |
| `execute_api_call(project, arguments)` | 执行实际 API 调用 |
| `apply_output_template(response, template)` | 应用输出模板 |

#### MCP Gateway (MCP 网关模块)
- **路径**: `backend/src/api2mcp/mcp_gateway/`
- **职责**: 提供 MCP JSON-RPC 2.0 协议端点
- **路由前缀**: `/mcpapi`

**支持的 JSON-RPC 方法**:
| 方法 | 说明 |
|------|------|
| `initialize` | 初始化 MCP 会话 |
| `notifications/initialized` | 客户端初始化完成通知 |
| `tools/list` | 列出所有活跃工具 |
| `tools/call` | 调用指定工具 |
| `ping` | 心跳检查 |

#### Core (核心模块)
- **路径**: `backend/src/api2mcp/core/`
- **职责**: 提供基础设施服务

| 模块 | 说明 |
|------|------|
| `logging.py` | LoggingMiddleware，请求日志记录 |
| `redis.py` | Redis 连接管理（可选） |

### 2.4 状态管理 (基于 Redis)

系统使用 Redis 实现全流程状态管理：

```python
# 主要状态管理器
- RequestStateManager    # 请求状态管理（追踪每个工具调用）
- ServerStateManager     # 服务实例状态管理（集群部署）
- CallStatisticsManager  # 调用统计管理（成功率、延迟等）
```

**状态数据**:
- 请求追踪 (request_id, tool_name, status, input/output, timestamp)
- 服务心跳 (server_id, name, status, last_heartbeat)
- 调用统计 (total_calls, success/failed, latency_ms, hourly_history)

### 5.2 潜在瓶颈与解决方案

| 模块 | 潜在瓶颈 | 解决方案 |
|------|----------|----------|
| Database | 连接池耗尽 | 使用 PgBouncer 连接池 |
| Redis | 单点故障 | Redis Cluster 集群 |
| API Registry | 频繁查询 | 缓存热点数据 |
| MCP Gateway | 高并发 | 水平扩展实例 |
| Engine | 转换耗时 | 异步任务队列 |
