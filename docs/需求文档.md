# API2MCP 需求文档

**记录项目的详细需求设计**

## 一、项目概述

### 1.1 项目背景

随着大语言模型（LLM）和 AI Agent 的快速发展，如何让 AI Agent 能够可靠地调用各种外部 REST API 成为一个关键问题。MCP（Model Context Protocol）作为一种新兴的 AI 工具调用协议，正在被越来越多的 AI 应用采用。

然而，许多企业现有的业务系统都采用传统的 REST API 架构，无法直接被 AI Agent 通过 MCP 协议调用。API2MCP 项目旨在解决这一难题，提供一个将传统 REST API 无缝转换为 MCP 工具的平台。

### 1.2 项目目标

1. **降低接入门槛** - 无需改造现有 API，即可快速生成 MCP 工具
2. **标准化输出** - 将各类 API 响应转换为统一的 MCP 格式
3. **简化管理** - 提供可视化管理界面，统一管理所有 API 工具
4. **可观测性** - 提供完整的请求追踪和调用统计功能

### 1.3 核心价值

| 价值 | 说明 |
|------|------|
| **零改造** | 不需要修改现有 REST API，即可生成 MCP 工具 |
| **快速接入** | 通过配置而非代码的方式，快速创建 MCP 工具 |
| **智能解析** | 支持 OpenAPI/Swagger 文档自动解析 |
| **灵活适配** | 支持请求模板、输出模板、变量替换等高级功能 |

## 二、功能需求

### 2.1 MCP 工具管理

#### 2.1.1 工具创建

**功能描述**: 用户可以通过以下方式创建 MCP 工具：

| 创建方式 | 说明 |
|----------|------|
| 手动配置 | 手动填写 API 信息、参数定义、鉴权配置等 |
| OpenAPI 导入 | 粘贴 OpenAPI/Swagger 文档 URL 或 JSON，自动解析生成工具定义 |
| 批量导入 | 支持批量导入多个 API 配置 |

**输入字段**:
| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| MCP 名称 | string | 是 | 工具唯一标识，用于 AI Agent 调用 |
| 版本号 | string | 是 | 默认 v1，支持多版本管理 |
| API 描述 | string | 否 | 工具功能描述 |
| API 方法 | enum | 是 | GET/POST/PUT/DELETE/PATCH |
| API 端点 | string | 是 | 完整 URL 或相对路径 |
| 分类 | string | 否 | 用于工具分类管理 |
| 输出字段 | string | 否 | JSONPath 表达式，指定返回字段 |
| 输出模板 | string | 否 | 自定义输出模板 |

#### 2.1.2 参数管理

**功能描述**: 支持复杂参数结构的树形管理

**参数属性**:
| 属性 | 说明 |
|------|------|
| 参数名称 | 参数唯一标识 |
| 参数类型 | string/number/boolean/array/object |
| 必填 | 是否必填 |
| 描述 | 参数说明，供 AI 理解 |
| 示例值 | 参数示例 |
| 默认值 | 参数默认值 |
| 枚举值 | 允许的值列表 |
| 单位 | 参数单位（如：元、秒、个） |
| 父参数 | 支持嵌套结构 |
| 语义标签 | AI 友好的语义描述 |

**语义标签**:
| 标签 | 说明 |
|------|------|
| search_keyword | 搜索关键词 |
| location | 地理位置 |
| date_range | 日期范围 |
| category | 分类筛选 |
| pagination | 分页参数 |
| sorting | 排序参数 |
| filter | 筛选条件 |

#### 2.1.3 鉴权配置

**支持的鉴权方式**:
| 类型 | 说明 |
|------|------|
| None | 无鉴权 |
| API Key | API 密钥认证（Header/Query） |
| Bearer Token | OAuth Bearer Token |
| Basic Auth | 用户名密码认证 |
| 自定义 Header | 自定义认证 Header |

#### 2.1.4 环境变量

**功能描述**: 支持全局变量和工具级别变量，用于：
- API 基础 URL 统一配置
- API Key 等敏感信息集中管理
- 不同环境（开发/测试/生产）配置切换

### 2.2 Smart Parser（智能解析）

#### 2.2.1 OpenAPI 解析

**功能描述**: 自动解析 OpenAPI 3.x / Swagger 2.0 文档

**解析内容**:
- API 端点和 HTTP 方法
- 参数定义（路径、查询、请求体）
- 响应结构
- 鉴权要求
- 标签和分类

#### 2.2.2 模板引擎

**功能描述**: 支持 Jinja2 风格的模板，用于：
- 请求参数转换
- 响应数据格式化
- 字段映射和重命名

### 2.3 MCP Server

#### 2.3.1 JSON-RPC 2.0 端点

**协议**: MCP JSON-RPC 2.0 over Streamable HTTP

**支持的端点**:
| 端点 | 说明 |
|------|------|
| `/mcpapi` | 根端点，列出所有活跃工具 |
| `/mcpapi/{identifier}` | 按 UUID 或工具名隔离 |
| `/mcpapi/{mcp_name}/{version}` | 按工具名+版本隔离 |

**支持的 JSON-RPC 方法**:
| 方法 | 说明 |
|------|------|
| `initialize` | 初始化 MCP 会话 |
| `notifications/initialized` | 客户端初始化完成通知 |
| `tools/list` | 列出所有可用工具 |
| `tools/call` | 调用指定工具 |
| `ping` | 心跳检查 |

#### 2.3.2 兼容端点

**为兼容不同 MCP 客户端，提供以下端点**:
| 端点 | 方法 | 说明 |
|------|------|------|
| `/mcpapi/list_tools` | POST | 列出所有工具 |
| `/mcpapi/tools` | GET/POST | 列出所有工具 |
| `/mcpapi/invoke_tool` | POST | 调用指定工具 |

### 2.4 状态管理

#### 2.4.1 请求追踪

**功能描述**: 追踪每个工具调用的完整生命周期

**追踪信息**:
- 请求 ID（唯一标识）
- 工具名称和版本
- 输入参数
- 输出结果
- 执行状态（pending/processing/completed/failed）
- 执行时间
- 错误信息（如有）

#### 2.4.2 调用统计

**功能描述**: 统计工具调用情况

**统计指标**:
| 指标 | 说明 |
|------|------|
| total_calls | 总调用次数 |
| success_count | 成功次数 |
| failed_count | 失败次数 |
| avg_latency_ms | 平均延迟（毫秒） |
| last_call_time | 最后调用时间 |
| hourly_history | 按小时的历史统计 |

#### 2.4.3 服务监控

**功能描述**: 监控服务实例状态

**监控信息**:
- 服务实例 ID
- 服务名称
- 运行状态
- 最后心跳时间

### 2.5 前端管理界面

#### 2.5.1 工具列表页

- 工具列表展示（名称、版本、分类、状态、创建时间）
- 搜索和筛选功能
- 批量操作（启用/禁用/删除）

#### 2.5.2 工具详情页

- 基本信息编辑
- 参数树形编辑器
- 鉴权配置
- 环境变量绑定
- MCP 定义预览
- 测试调用

#### 2.5.3 服务状态页

- 服务健康状态
- 实时调用统计
- 请求追踪列表
- 错误日志

## 五、使用场景

### 5.1 场景一：企业内部 API 接入

**背景**: 企业有多个内部 REST API，希望让 AI Agent 能够调用

**步骤**:
1. 管理员在平台上手动配置 API 信息
2. 配置参数定义和鉴权信息
3. 预览生成的 MCP 工具定义
4. 提交注册，MCP 工具即可被 AI Agent 调用

### 5.2 场景二：第三方 API 快速接入

**背景**: 需要快速接入第三方 OpenAPI

**步骤**:
1. 提供第三方 API 的 OpenAPI 文档 URL
2. 系统自动解析生成工具定义
3. 补充必要的鉴权和变量配置
4. 提交注册即可使用

### 5.3 场景三：AI Agent 工具调用

**背景**: AI Agent 需要调用 MCP 工具执行任务

**步骤**:
1. AI Agent 通过 MCP 客户端连接 `/mcpapi` 端点
2. 调用 `tools/list` 获取可用工具列表
3. 根据任务需求选择合适的工具
4. 调用 `tools/call` 执行工具，获取结果

## 七、API 评估标准

### 7.1 评分维度

| 维度 | 权重 | 评估要点 |
|------|------|----------|
| 参数语义化 | 20分 | 参数名是否自解释？是否有清晰的类型、枚举、单位描述？ |
| 参数确定性 | 20分 | 每个参数是否对应唯一的业务含义？参数间逻辑关系是否明确？ |
| 响应可理解性 | 20分 | 返回结构是否扁平？字段是否有业务描述？ |
| 文档完备性 | 20分 | 是否提供 OpenAPI/Swagger 文档？是否有请求/响应示例？ |
| 安全与扩展性 | 20分 | 是否存在注入风险？参数是否可枚举校验？ |

### 7.2 评级对照

| 总分 | 评级 | 处理建议 |
|------|------|----------|
| ≥ 80 | S 级 | 可直接自动注册为 MCP 工具 |
| 60-79 | A 级 | 可注册，建议按改造建议调整 |
| < 60 | B 级 | 不建议直接注册，需先改造接口 |
